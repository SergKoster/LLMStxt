## Доработки после теста владельца (2026-11-11)

- [x] **Схема в адресе подставляется сама.** Если пользователь ввёл адрес без `http://` / `https://`
  (например, `priisk.pro`), сервис дописывает схему сам, вводить её не нужно. Менять и проверку
  в браузере (`app.js` → `checkUrl`), и на сервере (`validation.py`), иначе сервер отклонит адрес.
  Решение владельца: сначала пробуем `https://`, если сайт по нему не открылся — `http://`.
  Если пользователь сам написал схему, ничего не меняем.
- [x] **Конкретная причина вместо общей ошибки «Не удалось прочитать страницы сайта…».**
  `llms-gen` при неудаче пишет только «No pages found», причину (403, 404, 5xx, таймаут)
  он показывает лишь в отладочном режиме. Решение владельца: свой проверочный запрос к
  стартовой странице делаем **только когда обход не удался**, при успехе лишних запросов нет.
  По ответу выбираем текст ошибки (черновик, тексты написал агент по просьбе владельца):

  | Что случилось | Текст для пользователя |
  |---|---|
  | 403/429 или страница «вы не робот» | Сайт защищён от автоматических программ и не отдаёт нам свои страницы. Сделать файл для этого сайта не получится. |
  | robots.txt запрещает обход | Владелец сайта запретил автоматический обход в файле robots.txt. Мы соблюдаем этот запрет, поэтому файл сделать нельзя. |
  | 401 | Сайт открывается только после входа по логину и паролю. Такие страницы мы прочитать не можем. |
  | 404 | По этому адресу страницы нет. Проверьте адрес. |
  | 5xx | Сайт сейчас работает с ошибкой. Попробуйте позже. |
  | Сайт не ответил | Сайт не ответил на запрос. Возможно, он временно недоступен. Попробуйте позже. |
  | Не открылся ни по https, ни по http | Не получилось открыть сайт ни по https://, ни по http://. Проверьте адрес. |
  | Ответ не HTML | По этому адресу находится не страница сайта, а файл. Укажите адрес страницы. |
  | Страница открылась, но текста нет | Сайт открылся, но текста на страницах нет: скорее всего, он появляется только после работы скриптов в браузере. Такой сайт мы прочитать не можем. |
  | Причину выяснить не удалось | Остаётся текущий общий текст. |

  Безопасность: пользователю показываем только свои заранее заготовленные тексты, а сырой вывод
  `llms-gen`, пути и адреса серверов — никогда. Проверочный запрос должен идти по тем же
  правилам, что и обход, в том числе не во внутреннюю сеть при редиректах.
  Проверочный запрос идёт только после неудачи, поэтому удачные генерации от него не медленнее.
- Разобрано: **dodopizza.ru не читается, и это не баг.** Сайт закрыт антибот-защитой
  (Servicepipe). На запрос `llms-gen` и даже на запрос к `robots.txt` отвечает 403 «ваши запросы
  похожи на автоматизированные». Если притвориться браузером, вместо сайта приходит страница
  JS-проверки или капчи. Обходить такую защиту не будем: сайт явно запрещает ботов. Для таких
  сайтов нужна понятная ошибка, см. пункт выше.
  Поиск в интернете (2026-11-11): антибот к robots.txt отношения не имеет, он оценивает сам запрос
  (TLS/HTTP-отпечаток, репутация IP, JS-проверка). Открытой программы «проверенных ботов» у
  Servicepipe нет (у Cloudflare есть Verified Bots и Web Bot Auth, но Додо не на Cloudflare).
  Законный путь один — попросить Dodo Brands внести наш IP/User-Agent в белый список.
- [x] Браузер брал старый `app.js` из кэша после обновления сервиса. Решение владельца — версия
