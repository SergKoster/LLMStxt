## Доработки после теста владельца (2026-11-11)

- [x] **Схема в адресе подставляется сама.** Если пользователь ввёл адрес без `http://` / `https://`
  (например, `priisk.pro`), сервис дописывает схему сам, вводить её не нужно. Менять и проверку
  в браузере (`app.js` → `checkUrl`), и на сервере (`validation.py`), иначе сервер отклонит адрес.
  Решение владельца: сначала пробуем `https://`, если сайт по нему не открылся — `http://`.
  Если пользователь сам написал схему, ничего не меняем.
- [x] **Конкретная причина вместо общей ошибки «Не удалось прочитать страницы сайта…».**
  `llms-gen` при неудаче пишет только «No pages found», причину (403, 404, 5xx, таймаут)
  он показывает лишь в отладочном режиме. Решение владельца: свой проверочный запрос к
  стартовой странице делаем **только когда обход не удался**, при успехе лишних запросов нет.
  По ответу выбираем текст ошибки (черновик, тексты написал агент по просьбе владельца):

  | Что случилось | Текст для пользователя |
  |---|---|
  | 403/429 или страница «вы не робот» | Сайт защищён от автоматических программ и не отдаёт нам свои страницы. Сделать файл для этого сайта не получится. |
  | robots.txt запрещает обход | Владелец сайта запретил автоматический обход в файле robots.txt. Мы соблюдаем этот запрет, поэтому файл сделать нельзя. |
  | 401 | Сайт открывается только после входа по логину и паролю. Такие страницы мы прочитать не можем. |
  | 404 | По этому адресу страницы нет. Проверьте адрес. |
  | 5xx | Сайт сейчас работает с ошибкой. Попробуйте позже. |
  | Сайт не ответил | Сайт не ответил на запрос. Возможно, он временно недоступен. Попробуйте позже. |
  | Не открылся ни по https, ни по http | Не получилось открыть сайт ни по https://, ни по http://. Проверьте адрес. |
  | Ответ не HTML | По этому адресу находится не страница сайта, а файл. Укажите адрес страницы. |
  | Страница открылась, но текста нет | Сайт открылся, но текста на страницах нет: скорее всего, он появляется только после работы скриптов в браузере. Такой сайт мы прочитать не можем. |
  | Причину выяснить не удалось | Остаётся текущий общий текст. |

  Безопасность: пользователю показываем только свои заранее заготовленные тексты, а сырой вывод
  `llms-gen`, пути и адреса серверов — никогда. Проверочный запрос должен идти по тем же
  правилам, что и обход, в том числе не во внутреннюю сеть при редиректах.
  Проверочный запрос идёт только после неудачи, поэтому удачные генерации от него не медленнее.
- Разобрано: **dodopizza.ru не читается, и это не баг.** Сайт закрыт антибот-защитой
  (Servicepipe). На запрос `llms-gen` и даже на запрос к `robots.txt` отвечает 403 «ваши запросы
  похожи на автоматизированные». Если притвориться браузером, вместо сайта приходит страница
  JS-проверки или капчи. Обходить такую защиту не будем: сайт явно запрещает ботов. Для таких
  сайтов нужна понятная ошибка, см. пункт выше.
  Поиск в интернете (2026-11-11): антибот к robots.txt отношения не имеет, он оценивает сам запрос
  (TLS/HTTP-отпечаток, репутация IP, JS-проверка). Открытой программы «проверенных ботов» у
  Servicepipe нет (у Cloudflare есть Verified Bots и Web Bot Auth, но Додо не на Cloudflare).
  Законный путь один — попросить Dodo Brands внести наш IP/User-Agent в белый список.
- [x] Браузер брал старый `app.js` из кэша после обновления сервиса. Решение владельца — версия
  в ссылке: `main.py` при старте дописывает к `app.js` и `style.css` отпечаток содержимого
  (`?v=…`), саму страницу отдаёт с `Cache-Control: no-cache`.

## Этап 3 — анализ сайта и пояснения (запрос владельца 2026-11-12)

Смысл: пользователь приходит улучшить свой сайт там, где сам не разбирается. Поэтому сервис
сначала смотрит сайт и предлагает, что сделать, а каждый файл объясняет: зачем он и что с ним делать.

Новый порядок работы с точки зрения пользователя:
1. Вводит адрес сайта → сервис анализирует сайт.
2. Видит список файлов: рекомендованные помечены, у каждого — пояснение и причина рекомендации.
3. Выбирает галочками, что сгенерировать (можно и нерекомендованное) → генерация как сейчас.
4. Скачивает файл(ы) вместе с пояснением, куда их положить.

Что не меняется: `POST /generate` и `GET /status/{task_id}` работают как в задании — критерии
приёмки (`docs/TASK.md`) должны проходить и дальше. Анализ — новый шаг перед ними, а не замена.

### 4.1 Файл `sitemap.xml`

Устройство (предложение агента): своего обхода сайта не пишем. Список страниц берём из того же
обхода `llms-gen`, который делает `llms.txt`: в готовом `llms.txt` уже есть адреса всех прочитанных
страниц, а страницы с `noindex` `llms-gen` пропускает сам. Если пользователь выбрал только
`sitemap.xml`, `llms-gen` всё равно запускается, но `llms.txt` пользователю не отдаём.
В карте будут только адреса, без даты изменения (`lastmod`): настоящих дат мы не знаем, а
выдуманные поисковики не учитывают.

**Решения владельца** (вопросы, до подшагов 4.1.3 и 4.1.5):
1. Рекомендовать ли карту одностраничнику? A — нет, если с главной нет ссылок на другие страницы
   этого же сайта (рекомендация агента: для priisk.pro карта ничего не даёт); B — да, всегда, когда
   карты нет.
2. Если сайт больше предела обхода (`MAX_PAGES` = 50), карта будет неполной. A — отдаём как есть и
   в инструкции пишем, что в карте только часть страниц (рекомендация агента); B — для таких
   сайтов карту не рекомендуем.
3. Тексты: пометка «на сайте нет sitemap.xml» / «у вас уже есть sitemap.xml», пояснение у галочки,
   раздел в `ИНСТРУКЦИЯ.txt` (положить в корень, добавить в `robots.txt` строку `Sitemap: …`,
   отправить карту в Яндекс.Вебмастер и Google Search Console). Черновик пишет агент.

**Ответы владельца (2026-11-13):**
1. A — одностраничнику не рекомендуем: карту рекомендуем, только если её нет и с главной есть
   ссылки на другие страницы этого же сайта.
2. Неполную карту отдаём, но с короткой пометкой, нужна ли полная и как её сделать. Формулировку
   пишет агент (владелец разрешил). Черновик: «В карту вошли первые 50 страниц сайта. Неполная
   карта не мешает: остальные страницы поисковики найдут по ссылкам. Если нужна полная карта —
   её обычно умеет делать сам конструктор или движок сайта (Тильда, WordPress, Битрикс): включите
   её в настройках.» Пометка — на странице у готового файла (один файл скачивается без инструкции)

### 4.2 Советы в двух группах: «важное» и «возможные рекомендации»

Предложение владельца: в «важное» — только то, что сервис проверяет надёжно и где ошибка
очевидна; в «возможные рекомендации» — то, что сервис видит, но владелец сайта мог сделать
нарочно, ради какой-то работы сайта.

Устройство (предложение агента): у совета (`site_checks.Advice`) появляется поле «группа»;
каждая проверка сама знает свою группу; API отдаёт её в каждом совете; страница показывает
две группы друг под другом внутри того же сворачиваемого отчёта.

Раскладка проверок (предложение агента, утверждает владелец):

| Проверка | Группа | Почему |
|---|---|---|
| `Disallow: /` в `robots.txt` для всех / Google / Яндекса | важное | Нарочно так делают только с закрытым или тестовым сайтом, а им наш сервис не нужен |
| `noindex` на главной или в заголовке ответа | возможное | Часто это нарочно: тестовая копия, закрытый сайт |
| Нет https / сертификат с ошибкой | важное | Ошибка без вариантов, браузер сам предупреждает посетителей |
| Ссылки с главной ведут на 404/410/5xx | важное | Битая ссылка — всегда ошибка |
| Без JS на главной почти нет текста | возможное | Так устроены сайты на React/Vue — это выбор, а не поломка |
| Нет title/description, одинаковые заголовки | возможное | Иногда страницы служебные и в поиск не нужны |
| Несуществующий адрес отвечает 200 | возможное | Так нарочно настраивают одностраничные приложения на JS |
| Нет viewport (отключено) | — | Владелец решил не возвращать (2026-11-13) |

**Решения владельца** (вопросы, до подшагов 4.2.2 и 4.2.3):
4. Раскладка из таблицы — так или поправить? Отдельно: `noindex` и `robots.txt` сейчас один совет
   «Сайт закрыт от поисковиков» — разделить на два (по группам), как в таблице?
5. Вернуть совет про viewport в «возможные рекомендации»? A — да (рекомендация агента); B — нет.
6. Названия групп. Черновик: «Важно исправить» и «Возможно, стоит поправить». Подпись под второй
   группой («это могло быть сделано нарочно») — нужна или нет (правило «ничего лишнего»)?
7. Что писать, когда важного нет, а возможное есть: A — строка «Серьёзных проблем не найдено» и
   ниже группа возможных (рекомендация агента); B — только группа возможных. И свёрнута ли группа
   возможных при появлении отчёта: A — развёрнута, как сейчас весь отчёт; B — свёрнута.

**Ответы владельца (2026-11-13):** 4 — раскладка как в таблице, «Сайт закрыт от поисковиков»

подписи под второй группой нет; 7 — нет важного, есть возможное: строка «Серьёзных проблем не

## На будущее

- **MCP-сервер для сайта** (запрос владельца 2026-11-12). MCP (Model Context Protocol) — способ,
  которым ИИ-ассистенты (Claude, ChatGPT и др.) подключаются к внешним сервисам и получают от них
  данные или выполняют действия. Для сайта это может быть, например, «найди на сайте ответ» или
  «запиши на приём». Варианты для нашего сервиса: рекомендации по настройке MCP-сервера для сайта
  пользователя или генерация заготовки такого сервера. Сначала разобраться, как это работает, кому
  из владельцев обычных сайтов это нужно и что можно сделать без своего сервера у пользователя.
  В `docs/RESEARCH.md` (раздел 3) MCP-карточки пока отмечены как «к обычному сайту не относится» —
  перепроверить.
- **Утечка ключей и служебных файлов** (ресёрч 2026-11-13, `docs/RESEARCH.md` раздел 5, «А»).
  Ключи сервисов в JS страницы, открытые `/.env` и `/.git/`. Сначала продумать, как не стать
  инструментом для поиска чужих ключей.

  открывается ли картинка, не остались ли заготовки шаблона (Lovable, «Vite + React»).
