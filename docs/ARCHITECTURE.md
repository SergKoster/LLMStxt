## Структура проекта

```

├── app/
│   ├── main.py          # FastAPI: маршруты, раздача статики, запуск уборки при старте

│   ├── tasks.py         # хранилище задач в памяти + фоновая функция
│   ├── generator.py     # обёртка над командой llms-gen (subprocess)

```

## Как идёт запрос

1. Браузер открывает `/` → `index.html`.
2. JS проверяет URL и шлёт `POST /generate {url}`.
3. Сервер: проверка URL → `task_id = uuid4()` → запись задачи со статусом `processing` →
   `BackgroundTasks.add_task(...)` → ответ `{task_id, status: "processing"}`.
4. Фоновая функция запускает `llms-gen`, ждёт до 180 секунд, пишет файл или текст ошибки.
5. JS каждые 3 секунды делает `GET /status/{task_id}`:
   - ответ JSON `processing` → ждать дальше;
   - ответ JSON `error` → показать текст ошибки;
   - ответ не JSON → это файл, сохранить его как `llms.txt`.

## API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/` | страница |
| POST | `/generate` | `200 {task_id, status: "processing"}` · `422 {detail}` при плохом URL |
| GET | `/status/{task_id}` | файл · `{status: "processing"}` · `{status: "error", error}` · `404` для неизвестного id |

## Решения по модулям

**validation.py**
- Схема только `http`/`https`, есть хост, длина до ~2000 символов.
- Хост должен резолвиться в DNS — иначе сразу понятная ошибка «сайт не найден».
- Запрет локальных и внутренних адресов (`localhost`, `127.0.0.0/8`, `10/8`, `192.168/16` и т.п.),
  чтобы через сервис нельзя было ходить во внутреннюю сеть сервера.

**tasks.py**
- Задачи — словарь в памяти: `task_id → {status, error, created_at}`. Базы нет.
- Следствие: uvicorn запускается **в один процесс** (`--workers 1`); после перезапуска контейнера
  незавершённые задачи теряются. Для MVP это нормально.
- Ограничение числа одновременных генераций (семафор), чтобы сервер не легли от десятка запросов.

**generator.py**
- `subprocess.run([...], timeout=180, capture_output=True)`, без `shell=True`.
- Команда: `llms-gen <url> --depth 3 --output <путь> --no-js --max-pages N --delay D`.
  - `--no-js` — без Playwright/Chromium, образ остаётся лёгким.
  - `--max-pages` и `--delay` **в задании нет, но без них критерий «habr.com за минуту» не выполнить**:
    у `llms-gen` пауза по умолчанию 1 с на запрос и нет лимита страниц. Точные числа подобрать
    при реализации на реальных сайтах.
- Файл пишется во временное имя и переименовывается, когда готов, — чтобы `/status` не отдал половину.
- Ошибки переводятся в понятный текст: таймаут, сайт не отвечает, пустой результат, код возврата ≠ 0.

**cleanup.py**
- Фоновый цикл при старте приложения: раз в несколько минут удаляет файлы в `/tmp/llms_outputs`
  старше 1 часа и записи задач из словаря.

**static/**
- Один экран: поле, кнопка, индикатор, блок ошибки. Тексты и внешний вид — по решению владельца.

## Что выяснилось при реализации (2026-11-10)

- **`llms-gen` соблюдает `Crawl-delay` из robots.txt сайта**, а файл пишет только в конце обхода.
  У habr.com пауза 10 секунд: 30 страниц шли 5 минут 19 секунд. Поэтому `generator.py` сам читает
  `Crawl-delay` и заранее считает `--max-pages` так, чтобы обход занял около минуты
  (`CRAWL_TIME_BUDGET_SECONDS`). Итог: habr.com — 5 страниц за 68 секунд, priisk.pro — 7 секунд.
- **`llms-gen` 0.3.2 ломает пункты списка**, если в заголовке или описании страницы есть перенос
  строки, — файл выходит невалидным. `fix_broken_entries()` в `generator.py` склеивает их обратно.
- Несуществующий сайт: `llms-gen` возвращает код 1 и `ERROR: No pages found`. До него дело обычно
  не доходит — адрес отсекает проверка DNS в `validation.py`.
- Страница: только поле, кнопка, индикатор и текст ошибки (решение владельца — ничего лишнего).
  Когда файл готов, появляются текст «Ваш файл готов» и кнопка «Скачать»; сам файл не скачивается.

## Что пока не проверено

- Сборка и запуск в Docker: на машине разработчика Docker Desktop 4.83 не стартует — Windows
  (сборка 26300) не даёт ему работать с файлами-сокетами (ошибка 1920), даже со свежесозданными.
  Проверить на сервере при выкладке или после починки Docker.
- Защита от внутренних адресов проверяет только введённый хост. Если внешний сайт перенаправит
  на внутренний адрес, `llms-gen` пойдёт по редиректу.
