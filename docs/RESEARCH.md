# Исследование (2026-11-10)

Собрано тремя сабагентами по открытым источникам. Запуск кода не проводился.
Многие источники по статистике — блоги SEO-компаний, цифры приблизительные.

## 1. Библиотека `llms-generator`

- PyPI: `llms-generator`, версия 0.3.2 (18.10.2026), MIT, Python 3.10+. Один автор, пакету ~5 месяцев.
- Зависимости: `requests`, `beautifulsoup4`. Ключи API и LLM не нужны.
- Команда `llms-gen`. Пример из README: `llms-gen https://example.com --depth 3 --output site-llms.txt`.
- Браузер не обязателен: Playwright ставится отдельно (`[js]`), нам не нужен.

| Флаг | Что делает |
|---|---|
| `--depth` | глубина обхода (по умолчанию 2) |
| `--output` | путь к файлу |
| `--full` | дополнительно пишет `llms-full.txt` |
| `--no-js` | отключает Playwright |
| `--delay` | пауза между запросами (по умолчанию 1.0 с) |
| `--timeout` | таймаут одного запроса (по умолчанию 30 с) |
| `--max-pages` | лимит страниц (0 — без лимита) |
| `--check` | проверка результата по спецификации |
| `--optional-paths` | пути для раздела `## Optional` |
| `--prefer-markdown` | ссылаться на `.md`-версии страниц, если есть |

Не подтверждено: флаги взяты из README в пересказе, реальное поведение 0.3.2 не проверялось.
Есть одноимённый пакет на npm — это другой инструмент, к заданию не относится.

Запасной вариант, если библиотека подведёт: свой обход на `httpx` + BeautifulSoup
(sitemap.xml → ссылки того же домена → `<title>` и meta description → Markdown).

Источники: https://pypi.org/project/llms-generator/ · https://github.com/aouwalitshikkha/llms-generator

## 2. Формат llms.txt

Спецификация: https://llmstxt.org/. Порядок частей:

1. `# Название` — единственная обязательная часть.
2. `> Краткое описание` — рекомендуется.
3. Обычный текст без заголовков — по желанию.
4. Секции `## Название` со списками `- [текст](url): описание` (описание необязательно).
5. Секция `## Optional` — второстепенные ссылки.

Файл лежит в корне сайта: `/llms.txt`.

```markdown
# Название сайта
> Одно-два предложения, что это за сайт.

## Документация
- [Быстрый старт](https://example.com/start): как начать за 5 минут

## Optional
- [Блог](https://example.com/blog): новости
```

**Что проверять в готовом файле** (для критерия «валидный llms.txt»):
- первая значимая строка — `# ...`, и такой заголовок один;
- между `#` и первым `##` нет других заголовков;
- секции — только `##`, глубже не идём;
- каждый пункт списка — `- [текст](url)` с необязательным `: описание`;
- ссылки абсолютные, `http(s)`; нет дублей;
- файл не пустой, UTF-8.

`llms-full.txt` — не часть спецификации, а соглашение: весь текст сайта одним файлом.
`.md`-версии страниц — часть спецификации, но их должен выложить на сайт сам владелец.

**Честно про пользу:** llms.txt — предложение, а не принятый стандарт. По исследованию Ahrefs,
97% таких файлов ни разу не запрашивались ИИ-ботами; Google заявляет, что файл не использует.
Реальная польза — документация и агенты, которым файл дают вручную. На странице сервиса нельзя
обещать рост трафика или видимости в ChatGPT.

Источники: https://llmstxt.org/ · https://www.ahrefs.com/blog/llmstxt-study/ ·
https://www.optimizely.com/field-notes/articles/does-llms-txt-work/

## 3. Дополнения (этап 2)

Решение владельца от 2026-11-10: берём `llms-full.txt`, аудит и проверку llms.txt.
`robots.txt` для ИИ-ботов пока не делаем. Остальное в таблице — справка на будущее.

Что делают похожие сервисы сверх llms.txt: `llms-full.txt`, проверка файла, аудит сайта,
учёт визитов ИИ-ботов. Больше почти ничего.

| Дополнение | Что это | Сложность у нас | Польза |
|---|---|---|---|
| `llms-full.txt` | весь текст сайта одним файлом | почти ноль: флаг `--full` | средняя |
| Проверка llms.txt | список найденных проблем в файле | низкая: правила из раздела 2 или `--check` | средняя |
| Аудит «готовность к ИИ» | отчёт: есть ли llms.txt, sitemap, закрыты ли ИИ-боты в robots.txt, meta description, JSON-LD | низкая: 4–5 запросов к сайту | высокая |
| `robots.txt` для ИИ-ботов | готовый блок правил: пускать всех / закрыть обучение / закрыть всех | низкая: шаблон | высокая |
| `sitemap.xml` | карта сайта | средняя: нужен свой список страниц | высокая, если карты нет |
| JSON-LD (Organization, WebSite) | разметка schema.org для вставки в сайт | средняя: разбор главной страницы | высокая |
| `security.txt` | контакт для сообщений об уязвимостях | низкая, но нужна форма с контактом | средняя |
| `ai.txt`, `tdmrep.json` | заявления о правах на обучение ИИ | низкая | низкая |
| `humans.txt` | — | — | нет смысла |
| MCP/A2A-карточки, `agents.json`, `ai-plugin.json`, `AGENTS.md` | для сайтов с собственным агентом или для репозиториев | — | к обычному сайту не относится |

**ИИ-боты для шаблона `robots.txt`:**
- обучение: `GPTBot`, `ClaudeBot`, `CCBot`, `Google-Extended`, `Applebot-Extended`, `Bytespider`,
  `meta-externalagent`, `Amazonbot`;
- поиск: `OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot`;
- по запросу пользователя: `ChatGPT-User`, `Claude-User`, `Perplexity-User`.

Частый выбор владельцев сайтов — закрыть обучение, но оставить поиск. Полный список ведётся в
репозитории `ai-robots-txt/ai.robots.txt` (перед реализацией сверить).
Дополнительно можно добавить строку Cloudflare `Content-Signal: search=yes, ai-train=no` — это
пожелание, а не блокировка.

https://www.searchenginejournal.com/ai-crawler-user-agents-list/ ·
https://www.layer3labs.io/comparisons/llms-txt-generators
