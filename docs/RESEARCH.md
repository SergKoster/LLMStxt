# Исследование (2026-11-10)

Собрано тремя сабагентами по открытым источникам. Запуск кода не проводился.
Многие источники по статистике — блоги SEO-компаний, цифры приблизительные.

## 1. Библиотека `llms-generator`

- PyPI: `llms-generator`, версия 0.3.2 (18.10.2026), MIT, Python 3.10+. Один автор, пакету ~5 месяцев.
- Зависимости: `requests`, `beautifulsoup4`. Ключи API и LLM не нужны.
- Команда `llms-gen`. Пример из README: `llms-gen https://example.com --depth 3 --output site-llms.txt`.
- Браузер не обязателен: Playwright ставится отдельно (`[js]`), нам не нужен.

| Флаг | Что делает |
|---|---|
| `--depth` | глубина обхода (по умолчанию 2) |
| `--output` | путь к файлу |
| `--full` | дополнительно пишет `llms-full.txt` |
| `--no-js` | отключает Playwright |
| `--delay` | пауза между запросами (по умолчанию 1.0 с) |
| `--timeout` | таймаут одного запроса (по умолчанию 30 с) |
| `--max-pages` | лимит страниц (0 — без лимита) |
| `--check` | проверка результата по спецификации |
| `--optional-paths` | пути для раздела `## Optional` |
| `--prefer-markdown` | ссылаться на `.md`-версии страниц, если есть |

Не подтверждено: флаги взяты из README в пересказе, реальное поведение 0.3.2 не проверялось.
Есть одноимённый пакет на npm — это другой инструмент, к заданию не относится.

Запасной вариант, если библиотека подведёт: свой обход на `httpx` + BeautifulSoup
(sitemap.xml → ссылки того же домена → `<title>` и meta description → Markdown).

Источники: https://pypi.org/project/llms-generator/ · https://github.com/aouwalitshikkha/llms-generator

## 2. Формат llms.txt

Спецификация: https://llmstxt.org/. Порядок частей:

1. `# Название` — единственная обязательная часть.
2. `> Краткое описание` — рекомендуется.
3. Обычный текст без заголовков — по желанию.
4. Секции `## Название` со списками `- [текст](url): описание` (описание необязательно).
5. Секция `## Optional` — второстепенные ссылки.

Файл лежит в корне сайта: `/llms.txt`.

```markdown
# Название сайта
> Одно-два предложения, что это за сайт.

## Документация
- [Быстрый старт](https://example.com/start): как начать за 5 минут

## Optional
- [Блог](https://example.com/blog): новости
```

**Что проверять в готовом файле** (для критерия «валидный llms.txt»). Для анализа чужих файлов
владелец решил (2026-11-12) проверять только основу — см. `docs/ARCHITECTURE.md`, «Этап 3»;
список ниже остаётся ориентиром для нашего собственного файла:
- первая значимая строка — `# ...`, и такой заголовок один;
- между `#` и первым `##` нет других заголовков;
- секции — только `##`, глубже не идём;
- каждый пункт списка — `- [текст](url)` с необязательным `: описание`;
- ссылки абсолютные, `http(s)`; нет дублей;
- файл не пустой, UTF-8.

`llms-full.txt` — не часть спецификации, а соглашение: весь текст сайта одним файлом.
`.md`-версии страниц — часть спецификации, но их должен выложить на сайт сам владелец.

**Честно про пользу:** llms.txt — предложение, а не принятый стандарт. По исследованию Ahrefs,
97% таких файлов ни разу не запрашивались ИИ-ботами; Google заявляет, что файл не использует.
Реальная польза — документация и агенты, которым файл дают вручную. На странице сервиса нельзя
обещать рост трафика или видимости в ChatGPT.

Источники: https://llmstxt.org/ · https://www.ahrefs.com/blog/llmstxt-study/ ·
https://www.optimizely.com/field-notes/articles/does-llms-txt-work/

## 3. Дополнения (этап 2)

Решение владельца от 2026-11-10: берём `llms-full.txt`, аудит и проверку llms.txt.
`robots.txt` для ИИ-ботов пока не делаем. Остальное в таблице — справка на будущее.

Что делают похожие сервисы сверх llms.txt: `llms-full.txt`, проверка файла, аудит сайта,
учёт визитов ИИ-ботов. Больше почти ничего.

| Дополнение | Что это | Сложность у нас | Польза |
|---|---|---|---|
| `llms-full.txt` | весь текст сайта одним файлом | почти ноль: флаг `--full` | средняя |
| Проверка llms.txt | список найденных проблем в файле | низкая: правила из раздела 2 или `--check` | средняя |
| Аудит «готовность к ИИ» | отчёт: есть ли llms.txt, sitemap, закрыты ли ИИ-боты в robots.txt, meta description, JSON-LD | низкая: 4–5 запросов к сайту | высокая |
| `robots.txt` для ИИ-ботов | готовый блок правил: пускать всех / закрыть обучение / закрыть всех | низкая: шаблон | высокая |
| `sitemap.xml` | карта сайта | средняя: нужен свой список страниц | высокая, если карты нет |
| JSON-LD (Organization, WebSite) | разметка schema.org для вставки в сайт | средняя: разбор главной страницы | высокая |
| `security.txt` | контакт для сообщений об уязвимостях | низкая, но нужна форма с контактом | средняя |
| `ai.txt`, `tdmrep.json` | заявления о правах на обучение ИИ | низкая | низкая |
| `humans.txt` | — | — | нет смысла |
| MCP/A2A-карточки, `agents.json`, `ai-plugin.json`, `AGENTS.md` | для сайтов с собственным агентом или для репозиториев | — | к обычному сайту не относится |

**ИИ-боты для шаблона `robots.txt`:**
- обучение: `GPTBot`, `ClaudeBot`, `CCBot`, `Google-Extended`, `Applebot-Extended`, `Bytespider`,
  `meta-externalagent`, `Amazonbot`;
- поиск: `OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot`;
- по запросу пользователя: `ChatGPT-User`, `Claude-User`, `Perplexity-User`.

Частый выбор владельцев сайтов — закрыть обучение, но оставить поиск. Полный список ведётся в
репозитории `ai-robots-txt/ai.robots.txt` (перед реализацией сверить).
Дополнительно можно добавить строку Cloudflare `Content-Signal: search=yes, ai-train=no` — это
пожелание, а не блокировка.

## 4. Простые проверки сайта для шага «анализ» (2026-11-12)

Вопрос владельца: что плохое или недоделанное на сайте видно сразу, без нейросети. Ресёрч делал
агент (Sonnet) по открытым источникам. Частоту проблем у маленьких сайтов он оценил сам —
статистики не нашёл.

Ограничения: только сырой HTML, заголовки ответа и несколько запросов, без браузера и JS.
Принцип показа: только то, что ведёт к одному из итогов «сайт не виден», «сайт сломан»,
«в выдаче будет пусто». Нет проблем — «серьёзных проблем не найдено», мелочи не искать.

Решение владельца (2026-11-12): берём проверки 1, 2, 5, 6, 7, 8; проверки 3, 4 и «в запасе» не
берём. Задачи — `docs/TASKS.md`, раздел 3.3.

**Кандидаты в первый вариант (рекомендация агента):**

| # | Проверка | Как проверить | Почему важно | Исправление |
|---|---|---|---|---|
| 1 | Сайт закрыт от индексации | `<meta name=robots content=noindex>`, заголовок `X-Robots-Tag: noindex`, `Disallow: /` в `robots.txt` для `*`, Googlebot, YandexBot | Сайт совсем не попадёт в поиск. Частый хвост тестовой версии и галочки WordPress | Совет, где снять |
| 2 | Сайт отвечает ошибками | Нет HTTPS / сертификат просрочен; страницы из обхода с 4xx/5xx | Браузер пишет «Небезопасно», посетитель упирается в ошибку | Совет; список битых ссылок |
| 3 | ИИ-боты для поиска закрыты | `robots.txt`: OAI-SearchBot, PerplexityBot, Claude-SearchBot (и отдельно обучающие GPTBot, ClaudeBot, Google-Extended, CCBot) | По документации OpenAI без OAI-SearchBot сайта нет в поиске ChatGPT | Готовый блок для `robots.txt` |
| 4 | Защита хостинга/CDN режет ботов | 403/429/страница проверки на наш запрос, хотя `robots.txt` разрешает | Боты не видят сайт, хотя владелец «всё открыл» | Совет |
| 5 | Главная пустая без JS | Видимого текста в сыром HTML < ~200 символов, есть `<div id="root">` / `__next` | Большинство ИИ-ботов не выполняют JS (вторичные источники) | Совет |
| 6 | Нет `<meta name=viewport>` | Тег в `<head>` | На телефоне сайт мелкий; Яндекс пишет «не оптимизирован для мобильных» | Готовая строка |
| 7 | Нет `title`/`description` или одинаковые на страницах | Теги на страницах из обхода | Это заголовок и подпись в выдаче; есть в Яндекс.Вебмастере и Lighthouse | Совет, одним пунктом |
| 8 | Несуществующий адрес отдаёт 200 вместо 404 | `GET /случайная-строка` | Есть в диагностике Яндекса; владелец сам не увидит | Совет |

В запасе (показывать только при явной ошибке): нет 301 на один адрес из http/https/www;
`canonical` на чужой или тестовый домен; `robots.txt` отдаётся через редирект (Яндекс его тогда
не учитывает); `sitemap.xml` — только сайтам больше ~5 страниц (можем сгенерировать сами).

**Не показывать:** длину title/description (Google: рекомендаций по длине нет), число слов,
meta keywords, структуру h1–h6, alt у всех картинок, скорость (без браузера — гадание),
Schema.org «для ИИ» и «GEO-баллы» (Google: специальная разметка для AI Overviews не нужна),
nofollow, hreflang, `Clean-param`, `Host`, `Crawl-delay`. Open Graph, `lang`, favicon — мелочи,
не в первом списке.

**Про ИИ-видимость честно.** Подтверждено документацией: у OpenAI разные боты для поиска
(OAI-SearchBot) и обучения (GPTBot) — обучение можно закрыть без потери поиска; Google для
AI Overviews ничего особого не требует, нужна обычная индексация и текст в HTML. Не подтверждено:
что `llms.txt` повышает цитируемость.

**Замечания агента-исполнителя (не из ресёрча):**
- Проверка 3 даёт готовый блок `robots.txt` — владелец ранее решил `robots.txt` пока не делать.
- Проверку 4 ресёрч предлагал делать запросами с чужим User-Agent (Googlebot, YandexBot). Это
  выдача себя за чужого бота, а крупные сайты проверяют настоящий Googlebot по DNS и всё равно
  ответят иначе. Предлагаю проверять только своим User-Agent — то же, что уже делает `probe.py`.
- Проверки 2, 4, 5 частично уже есть в `probe.py` (тексты ошибок обхода).

## 5. Частые проблемы у тех, кто делает сайт сам (2026-11-13)

Вопрос владельца: что чаще всего ломают непрофессионалы (вайбкодинг, конструкторы) и что наш сервис
может поймать без нейросети. Источники — форумы, статьи-аудиты, новости; многие статьи от компаний,
которые продают своё решение, поэтому цифры — ориентир, а не статистика.

Что уже покрыто анализом: пустая главная без JS (проверка 5), `noindex`/`robots.txt` (1),
title/description (7). Ниже — только то, что не покрыто и не мелочь. Это **предложения агента**,
ничего не реализуется без «да» владельца.

| # | Предложение | Почему стоит | Как проверить без ИИ | Сложность |
|---|---|---|---|---|
| А | Утечка ключей и файлов | Самая громкая беда вайбкод-сайтов: ключи OpenAI/Stripe/Supabase `service_role` вшиты в JS страницы; аудит 50 приложений — у 78% секреты в публичных переменных. Открытые `/.env` и `/.git/` — сотни тысяч сайтов в сканах | Скачать JS со страниц обхода, искать известные виды ключей по шаблону (`sk-…`, `sk_live_…`, JWT с `"role":"service_role"`, `AKIA…`); запросить `/.env`, `/.git/HEAD` | средняя |
| Б | Превью ссылки в мессенджерах | Самая частая жалоба после «не индексируется»: в Telegram/WhatsApp/VK ссылка без картинки или с чужой (логотип Lovable, «Vite + React»). У большинства из 100 разобранных вайбкод-сайтов неполные OG-теги | Есть ли `og:title`, `og:image`; адрес картинки полный, по HTTPS, открывается, не WebP; заготовки шаблона в title/OG/favicon | низкая |
| В | Персональные данные (152-ФЗ) | На сайте форма заявки, но нет политики конфиденциальности; или данные уходят в Google Forms/Analytics. Штрафы с 30.05.2025 — сотни тысяч рублей. Для российских сайтов (priisk.pro) — самое денежное | `<form>` с полями телефон/почта/имя и нет ссылки со словами «политика», «конфиденциальн», «персональн»; скрипты `google-analytics.com`, `googletagmanager.com`, ссылки `docs.google.com/forms` | низкая |
| Г | `sitemap.xml` | Один из главных советов на вопрос «почему сайт не в поиске» (Тильда, Lovable); конструкторы и ИИ часто делают её с ошибками или не делают | Нет `/sitemap.xml` или в ней битые/чужие адреса. Файл можно сгенерировать из того, что уже обошли | средняя |

Оговорки:
- **А** — проверка двойного назначения: тем же способом злоумышленник найдёт ключ на чужом сайте.
  Мы не знаем, чей сайт. Смягчение: не показывать сам ключ, только вид ключа и что делать
  (отозвать и выпустить новый). Базу Supabase (включён ли RLS) **не проверять** — это уже доступ
  к чужим данным. Ключи Firebase (`AIza…`) и Supabase `anon` публичны по задумке — не ругаться на них.
- **В** — не юридическая консультация. Про Google Analytics эксперты спорят (запрет сбора в
  иностранные базы с 01.07.2025 по 23-ФЗ), поэтому формулировка мягкая: «данные уходят за границу,
  это риск». Генерировать текст политики не предлагаю — это работа юриста.
- **Г** — в разделе 4 sitemap был «в запасе» с порогом ~5 страниц; для одностраничника не нужен.

Не предлагаю (мелочь или нужен браузер/ИИ): alt у картинок, структура заголовков, скорость,
favicon отдельно, старый год в подвале, проверка подключения Вебмастера (по HTML не видно).
